# AIChatServer 前后端接口文档

> 本文档描述 AIChatServer 对外提供的全部 HTTP 接口，涵盖请求路径、请求方式、请求/响应参数（类型与名称）以及响应状态码。

## 1. 基本信息

| 项目 | 说明 |
|---|---|
| 服务地址 | `http://<server_ip>:<server_port>`（默认 `0.0.0.0:8080`，配置文件可修改） |
| 数据格式 | JSON（流式接口为 `text/event-stream`） |
| 字符编码 | UTF-8 |
| 静态页面 | 根路径 `/` 映射到 `www` 目录（相对服务器进程工作目录） |

### 1.1 通用响应结构

所有非流式接口返回统一的 JSON 结构：

```json
{
  "success": true,
  "message": "提示信息",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| success | boolean | 请求是否成功 |
| message | string | 提示信息（成功时为描述文本，失败时为错误原因） |
| data | object / array | 业务数据，因接口而异；**失败时可能不存在** |

### 1.2 通用响应状态码

| 状态码 | 含义 |
|---|---|
| 200 | 请求成功 |
| 400 | 请求参数错误（JSON 解析失败 / 参数缺失 / 业务失败，如会话不存在、删除失败等） |
| 404 | 路径不存在或静态资源未找到 |
| 500 | 服务器内部错误（服务器未运行） |

---

## 2. 接口列表

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/sessions` | 获取会话列表 |
| GET | `/api/models` | 获取可用模型列表 |
| POST | `/api/session` | 创建会话 |
| GET | `/api/session/{id}/history` | 获取指定会话的历史消息 |
| DELETE | `/api/session/{id}` | 删除指定会话 |
| POST | `/api/message` | 全量发送消息（一次性返回完整回复） |
| POST | `/api/message/async` | 流式发送消息（SSE 增量返回） |

---

## 3. 接口详情

### 3.1 获取会话列表

- **路径**: `/api/sessions`
- **方法**: `GET`
- **请求参数**: 无

**响应 200**:

```json
{
  "success": true,
  "message": "get session list success",
  "data": [
    {
      "id": "1700000000000_1",
      "model": "deepseek-v4-flash",
      "createTime": 1754380800,
      "lastUpdateTime": 1754380999,
      "messageCount": 3,
      "lastUserMessage": "你好，帮我写一段代码"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| data[].id | string | 会话唯一 ID |
| data[].model | string | 会话使用的模型名称 |
| data[].createTime | number | 创建时间戳，**单位：秒** |
| data[].lastUpdateTime | number | 最后更新时间戳，**单位：秒** |
| data[].messageCount | integer | 会话内消息总条数 |
| data[].lastUserMessage | string（可选） | 最后一条用户消息内容；会话为空时不返回该字段 |

**响应状态**:

| 状态码 | 触发条件 | 响应体 |
|---|---|---|
| 200 | 成功 | 上述结构 |
| 500 | 服务器未运行 | `{"success": false, "message": "server is not running"}` |

### 3.2 获取可用模型列表

- **路径**: `/api/models`
- **方法**: `GET`
- **请求参数**: 无

**响应 200**:

```json
{
  "success": true,
  "message": "get model list success",
  "data": [
    { "model": "deepseek-r1:1.5b", "desc": "本地部署 deepseek-r1:1.5b 模型" },
    { "model": "deepseek-v4-flash", "desc": "" }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| data[].model | string | 模型名称（创建会话时需传入） |
| data[].desc | string | 模型描述 |

**响应状态**:

| 状态码 | 触发条件 | 响应体 |
|---|---|---|
| 200 | 成功 | 上述结构 |
| 400 | 模型列表为空 | `{"success": false, "message": "get model list failed"}` |
| 500 | 服务器未运行 | `{"success": false, "message": "server is not running"}` |

---

### 3.3 创建会话

- **路径**: `/api/session`
- **方法**: `POST`
- **Content-Type**: `application/json`

**请求参数（body）**:

```json
{
  "model": "deepseek-v4-flash"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| model | string | 是 | 模型名称，取自 `/api/models` 返回的 `data[].model` |

**响应 200**:

```json
{
  "success": true,
  "message": "create session success",
  "data": {
    "session_id": "1700000000000_1",
    "model": "deepseek-v4-flash"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| data.session_id | string | 新创建的会话 ID，后续接口均需携带 |
| data.model | string | 会话使用的模型名称（原样回显） |

**响应状态**:

| 状态码 | 触发条件 | 响应体 |
|---|---|---|
| 200 | 创建成功 | 上述结构 |
| 400 | body JSON 解析失败 / 创建会话失败 | `{"success": false, "message": "<解析错误> / create session failed"}` |
| 500 | 服务器未运行 | `{"success": false, "message": "server is not running"}` |

---

### 3.4 获取指定会话的历史消息

- **路径**: `/api/session/{id}/history`
- **方法**: `GET`

**请求参数（路径）**:

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | 是 | 会话 ID，URL 中的 `{id}` 部分 |

**响应 200**:

```json
{
  "success": true,
  "message": "get history messages success",
  "data": [
    {
      "id": "1700000000000_1_1",
      "role": "user",
      "content": "你好",
      "timestamp": 1754380800
    },
    {
      "id": "1700000000000_1_2",
      "role": "assistant",
      "content": "你好，请问有什么可以帮你？",
      "timestamp": 1754380820
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| data[].id | string | 消息唯一 ID |
| data[].role | string | 消息角色：`user`（用户）或 `assistant`（模型） |
| data[].content | string | 消息内容 |
| data[].timestamp | number | 消息发送时间戳，**单位：秒** |

**响应状态**:

| 状态码 | 触发条件 | 响应体 |
|---|---|---|
| 200 | 成功（会话无消息时 `data` 为空数组） | 上述结构 |
| 400 | 会话不存在 | `{"success": false, "message": "get history messages failed"}` |
| 500 | 服务器未运行 | `{"success": false, "message": "server is not running"}` |

### 3.6 全量发送消息

- **路径**: `/api/message`
- **方法**: `POST`
- **Content-Type**: `application/json`

**请求参数（body）**:

```json
{
  "sessionId": "1700000000000_1",
  "message": "请用一句话介绍你自己"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| sessionId | string | 是 | 会话 ID（由创建会话接口返回） |
| message | string | 是 | 用户消息内容，不能为空 |

**响应 200**:

```json
{
  "success": true,
  "message": "send message success",
  "data": {
    "response": "我是基于 AI_SDK_CPP 构建的智能聊天助手……",
    "sessionId": "1700000000000_1"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| data.response | string | 模型的完整回复文本 |
| data.sessionId | string | 会话 ID（原样回显） |

**响应状态**:

| 状态码 | 触发条件 | 响应体 |
|---|---|---|
| 200 | 发送成功并取得回复 | 上述结构 |
| 400 | JSON 解析失败 / `sessionId` 或 `message` 为空 / 模型未返回回复 | `{"success": false, "message": "<原因>"}` |
| 500 | 服务器未运行 | `{"success": false, "message": "server is not running"}` |

### 3.7 流式发送消息（SSE）

- **路径**: `/api/message/async`
- **方法**: `POST`
- **Content-Type**: `application/json`
- **响应 Content-Type**: `text/event-stream`（长连接，增量推送）

**请求参数（body）**:

```json
{
  "sessionId": "1700000000000_1",
  "message": "请用一句话介绍你自己"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| sessionId | string | 是 | 会话 ID |
| message | string | 是 | 用户消息内容 |

**响应（SSE 事件流）**:

首帧为空的起始帧，随后每帧为模型增量内容，最后以 `[DONE]` 结束：

```text
data: ""

data: "我是基于"
data: " AI_SDK_CPP "
data: "构建的智能聊天助手"

data: [DONE]
```

| 帧格式 | 说明 |
|---|---|
| `data: "<json字符串>"` | 增量内容。内容经 JSON 字符串转义（`Json::valueToQuotedString`），客户端需用 `JSON.parse` 反序列化后拼接 |
| `data: [DONE]` | 流结束标志，服务端在模型回复完毕时发送 |
| `data: ""` | 首帧空数据，用于建立/激活流 |

**注意事项**:

1. 流以 `\n\n` 分隔事件（SSE 标准）。
2. **服务端可能不发送 `[DONE]`**（例如模型流式异常中断时）。客户端应在 HTTP 流结束（`reader.read()` 返回 `done`）时强制收尾，避免光标/加载状态残留。
3. 响应头包含 `Cache-Control: no-cache` 与 `Connection: keep-alive`。

**响应状态**:

| 状态码 | 触发条件 | 响应体 |
|---|---|---|
| 200 | 流式连接建立，后续推送 SSE 帧 | 上述事件流 |
| 400 | body JSON 解析失败 | `{"success": false, "message": "<解析错误>"}` |
| 500 | 服务器未运行 | `{"success": false, "message": "server is not running"}` |

## 4. 接口调用示例

### 4.1 curl 示例

```bash
# 获取会话列表
curl http://127.0.0.1:8080/api/sessions

# 获取模型列表
curl http://127.0.0.1:8080/api/models

# 创建会话
curl -X POST http://127.0.0.1:8080/api/session \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-v4-flash"}'

# 获取历史消息
curl http://127.0.0.1:8080/api/session/1700000000000_1/history

# 删除会话
curl -X DELETE http://127.0.0.1:8080/api/session/1700000000000_1

# 全量发送消息
curl -X POST http://127.0.0.1:8080/api/message \
  -H "Content-Type: application/json" \
  -d '{"sessionId": "1700000000000_1", "message": "你好"}'

# 流式发送消息
curl -N -X POST http://127.0.0.1:8080/api/message/async \
  -H "Content-Type: application/json" \
  -d '{"sessionId": "1700000000000_1", "message": "你好"}'
```

### 4.2 典型前端调用时序

1. 页面加载：`GET /api/models` 获取模型列表 → `GET /api/sessions` 获取会话列表。
2. 新建会话：弹窗选择模型 → `POST /api/session` 得到 `session_id`。
3. 发送消息：`POST /api/message/async` 建立 SSE 流，逐帧渲染增量内容。
4. 切换会话：`GET /api/session/{id}/history` 渲染历史消息。
5. 删除会话：`DELETE /api/session/{id}` 后刷新会话列表。
