# AIChatServer 配置文件编写说明

本文档是 `env.conf` 的编写规范（唯一事实源）。配置模板见同目录 `env.conf.example`。

## 1. 配置文件位置与加载

| 场景 | 路径 |
|---|---|
| 默认 | 可执行文件上一级目录的 `env.conf`（从 `build/` 启动即找到 `ChatServer/env.conf`） |
| 自定义 | 命令行 `--config_file=<path>` 指定其他路径 |
| 文件不存在 | 使用内置默认值启动，并打印提示（模板参考 `.example`） |
| JSON 非法 | 启动失败，提示参考模板 |

## 2. 参数优先级

**命令行显式参数 > 配置文件 > 内置默认值**

- 命令行可覆盖的标量参数：`--server_ip`、`--server_port`、`--log_level`、`--temperature`、`--max_tokens`、`--log_file`、`--config_file`
- 模型列表（`models` 数组）只能通过配置文件指定，命令行无法覆盖

## 3. 配置结构总览

```json
{
  "server": { ... },        // 服务器参数（对象）
  "temperature": 0.7,       // 全局模型温度
  "max_tokens": 2048,       // 全局最大 token 数
  "models": [ ... ]         // 模型列表（数组）
}
```

## 4. server 节字段

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `ip` | string | `0.0.0.0` | 服务器绑定地址 |
| `port` | integer | `8080` | 监听端口（1~65535） |
| `log_level` | string | `INFO` | 日志级别：TRACE / DEBUG / INFO / WARN / ERROR / FATAL |
| `log_file` | string | `stdout` | 日志输出：`stdout`（控制台）或日志目录/文件路径 |
| `data_dir` | string | `data` | 数据库存放目录（数据库文件名固定为 `chatDB.db`） |

**路径锚定规则**：`log_file` 与 `data_dir` 的相对路径均锚定**可执行文件上一级目录**（即 `ChatServer/`），绝对路径直接使用；目录不存在时自动创建。

示例：`"log_file": "logs"` → `ChatServer/logs/AIChatServer.log`；`"data_dir": "data"` → `ChatServer/data/chatDB.db`。

## 5. 全局模型参数

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `temperature` | number | `0.7` | 模型温度，取值范围 [0, 2]，模型条目可覆盖 |
| `max_tokens` | integer | `2048` | 模型生成最大 token 数（非负），模型条目可覆盖 |

## 6. models 数组

### 6.1 provider 类型

| provider | 类型 | 特殊要求 |
|---|---|---|
| `ollama` | 本地模型 | 必须提供 `endpoint` |
| `deepseek` | 云端模型 | 无 |
| `gemini` | 云端模型 | 无 |
| `chatgpt` | 云端模型 | `openai` 视为 `chatgpt` |

### 6.2 字段说明

| 字段 | 类型 | 必填 | 适用 | 说明 |
|---|---|---|---|---|
| `provider` | string | 是 | 全部 | 模型提供方 |
| `name` | string | 是 | 全部 | 模型名称（全配置内唯一，创建会话时使用） |
| `api_key` | string | 否 | 云端 | API Key，**留空时回退环境变量** |
| `endpoint` | string | 是(ollama) | ollama | Ollama 服务地址，如 `http://127.0.0.1:11434` |
| `temperature` | number | 否 | 全部 | 覆盖全局温度 |
| `max_tokens` | integer | 否 | 全部 | 覆盖全局 max_tokens |
| `desc` | string | 否 | 全部 | 模型描述，展示于 `/api/models`；未配置时回退各 Provider 默认文案 |

### 6.3 多模型注册

同一 provider 可注册多个模型（如多个 `deepseek`），各自独立 `temperature` / `max_tokens` / `desc`；`name` 全局唯一，重复时后者注册失败。

### 6.4 API Key 规则

模型条目的 `api_key` 优先；为空时按 provider 回退环境变量：

| provider | 环境变量 |
|---|---|
| deepseek | `DEEPSEEK_API_KEY` |
| gemini | `GEMINI_API_KEY` |
| chatgpt | `CHATGPT_API_KEY`（兼容 `OPENAI_API_KEY`） |

> 建议日常使用环境变量方式，`api_key` 字段仅在需要为单个模型指定独立 Key 时使用。

### 6.5 desc 说明

`desc` 是**模型描述**（会展示给前端用户），不是字段说明。不要在其中写配置说明文字。

## 7. 完整示例

```json
{
  "server": {
    "ip": "0.0.0.0",
    "port": 8080,
    "log_level": "INFO",
    "log_file": "logs",
    "data_dir": "data"
  },
  "temperature": 0.7,
  "max_tokens": 2048,
  "models": [
    { "provider": "deepseek", "name": "deepseek-v4-flash", "desc": "DeepSeek 通用对话模型" },
    { "provider": "deepseek", "name": "deepseek-r1", "temperature": 0.5, "max_tokens": 4096, "desc": "DeepSeek 推理模型" },
    { "provider": "ollama", "name": "deepseek-r1:1.5b", "endpoint": "http://127.0.0.1:11434", "desc": "本地推理模型" }
  ]
}
```

## 8. 注意事项

- **API Key 安全**：`env.conf` 已被 `.gitignore` 忽略，但含 `api_key` 的配置请勿提交到版本库；优先使用环境变量
- **运行期数据**：数据库 `data/chatDB.db` 与日志 `logs/` 均在 `ChatServer/` 下，替换 `build/` 不影响数据；历史版本的数据在 `build/chatDB.db`，如需保留请迁移到 `data/`
- **模型可用性**：云端模型若无有效 API Key 会在启动校验阶段直接报错退出；本地模型必须能访问 `endpoint`
